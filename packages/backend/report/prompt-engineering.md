# 답변 품질 평가와 프롬프트 개선 과정 보고

기간: 2026-11-11 ~ 2026-11-12 · 대상: backend 답변 생성 프롬프트(`PROMPT_VERSION` v2 → v3 → v4 시도 → v3 유지)

버전별 가설·변경·수치의 요약은 [`../PROMPT_LOG.md`](../PROMPT_LOG.md)에 있다. 이 문서는 **어떤 순서로, 왜 그렇게 진행했는지**를 남긴다.

## 1. 목표와 원칙

- 목표: 답변 품질을 측정해 베이스라인을 정하고, 점수가 낮은 문항을 중심으로 프롬프트를 한 가지씩 고쳐 버전을 올리며 비교한다.
- 프로젝트 구조를 우선한다. 교안(llmops ch02/ch03)은 참고만 했다: 문항별 비교, 회귀 규칙, 개발/홀드아웃 분리, 같은 조건 비교.
- 정답 정보(`reference_answer` 등)는 프롬프트·서비스 경로에 넣지 않는다. 골든 데이터는 평가기와 러너만 쓴다.
- 팀 결정으로 고정: 검색은 hybrid_rerank, k=10. 프롬프트 개선은 이 조건에서만 비교한다.

## 2. 준비 (0단계)

1. 실제로는 k=10이 어디에도 설정돼 있지 않았다. 답변 생성의 검색 개수 기본값을 10으로 하고 `ANSWER_K`(1~50)로 바꿀 수 있게 했다 (PR #46).
2. 답변 평가 보고서에 k·프롬프트 버전, 문항별 답변·사유·검색된 문맥·trace_id를 남기고 평가 기본 검색 방식을 hybrid_rerank로 맞췄다 (PR #47). 이후 보고서끼리 같은 조건인지 확인할 수 있다.
3. 직전 작업(PR #42): 되묻기 직후 질문은 이전 되묻기 질문을 붙여 검색한다.

## 3. 베이스라인 (v2)

- 60문항(development 30 + additional 30), 온도 0·reasoning none, 캐시 끔, 2회 측정, 보안 문항 비교 1회.
- 노이즈 측정: 같은 조건 2회에서 facts ±0.035, faithfulness ±0.035, decision ±0.01 정도 흔들리고 문항 3건 안팎이 뒤집힌다. 한 번의 점수 차이로 개선을 주장하지 않기로 했다.
- 원인 분석: 근거가 모두 검색된 문항은 decision .96·facts .98, 일부만 검색된 문항은 .446·.411. 실패의 대부분은 검색 한계이고, 프롬프트로 건드릴 수 있는 것은 **과한 되묻기**(자료에 없다는 이유로 자료를 보내 달라고 되묻기)와 **되묻기 내용의 질**이다.

## 4. 반복 1: v3

- 가설: 되묻기를 "사용자만 아는 조건"으로 한정하고, 일부만 확인되면 answered로 두되 확인 안 되는 부분을 짚게 하면 과한 되묻기가 줄어든다.
- 결과: 되묻기 5~7건 → 1건. 그러나 점수는 노이즈 범위, 줄어든 되묻기는 보류로 이동. 보류가 정답인 3문항(IS-DEV-26, ADD-14, ADD-30)의 상태가 "answered"로 어긋났다(답 내용은 "확정할 수 없다"로 같음).

## 5. 반복 2: v4

- 가설: 핵심 결론(확정·계산·승인)을 낼 수 없으면 일부 사실을 확인했어도 abstained로 한다고 명시하면 3문항이 복구된다.
- 결과: 3문항 복구(1건은 API 오류로 판정 불가). 그러나 답해야 하는 문항의 보류가 9건으로 늘고 faithfulness가 내려갔다. decision은 v3와 같다.

## 6. 결정

- 사전 합의: v4에서 유의미한 성과가 없으면 v3로 돌아온다. → v4 미채택, `PROMPT_VERSION = "v3"` 유지.
- v3·v4 모두 v2 대비 점수 개선은 노이즈 범위 안이다. v3가 확실히 주는 것은 "자료 없음 → 자료 요청 되묻기"의 감소다.
- 프롬프트로 더 올릴 여지는 작다. 남은 실패는 근거 검색 누락(예약 창구, VGM 제출처 등)이라 검색 쪽(질문을 하위 질문으로 나눠 검색 등)을 팀과 논의해야 한다.

## 7. 운영에서 배운 점

- 측정이 느린 이유는 로컬 연산이 아니라 채점 호출(RAGAS·Judge)의 모델 API 대기다. v3 2회차 24분, v4는 병렬 2회 중 1회가 약 65분 멈추고 1회는 `model_failed` 1건. **병렬 실행하지 않는다.**
- 이미지 재빌드 약 8분. 프롬프트만 바꿀 때도 cli 이미지를 다시 빌드해야 한다.
- Git Bash는 `/app/...` 경로를 윈도 경로로 바꾼다. `MSYS_NO_PATHCONV=1`과 상대 경로 `--out eval_reports/…`를 쓴다.
- 평가 때만 `-e LLM_TEMPERATURE=0 -e LLM_REASONING_EFFORT=none`으로 덮어쓴다(`.env`는 온도 1).

## 8. 재현

```bash
MSYS_NO_PATHCONV=1 docker compose -f docker-compose.yml -f docker-compose.gpu.yml --profile tools run --rm \
  -e LLM_TEMPERATURE=0 -e LLM_REASONING_EFFORT=none cli eval-answer \
  --split development --split additional --mode hybrid_rerank --concurrency 2 --out eval_reports/<이름>.json
```
